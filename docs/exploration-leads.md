# Exploration lead directions and checked status

`@speleodb/map-core` owns the structured `directions` entries and geographic
cone generation. This package owns their common map presentation and compass
controls; applications own permissions, drafts, persistence and map lifecycle.

## Map layers

`createExplorationLeadConeLayer` creates a fill specification for the unchecked
bearings generated by `buildExplorationLeadCones`. Consumers pass source and
layer IDs, category visibility and their project filter. Cones retain their
fifteen-metre radius, 45-degree opening, red fill and eighty-percent opacity.
Use `EXPLORATION_LEAD_CONE_SOURCE_OPTIONS` for zero simplification tolerance.
Place cones above lead icons; they remain decorative rather than hit targets.

`createExplorationLeadMarkerLayer` supplies the symbol or circle fallback with a
common completion filter, color and opacity. `is_fully_checked` is the
calculated feature property used by the renderer. An ExplorationLead with any
unchecked entry retains its normal red marker. Fully checked markers are hidden
unless `showChecked` is true; when shown, they are green at seventy-five-percent
opacity. Fallback circle strokes use the same opacity as their fill. The shared
`EXPLORATION_LEAD_SHOW_CHECKED_DEFAULT` is false.

`explorationLeadFilter(showChecked, filter)` composes completion with the
caller's project filter. Reapply this composition when project visibility
changes, rather than replacing it with the project filter alone. Category and
country gates still apply. Keep all source features cached; visibility settings
do not delete data or affect synchronization. Settings-only changes update
filters and do not regenerate cones.

`MAP_LAYER_MIN_ZOOM.EXPLORATION_LEAD_SYMBOL` is the common zoom threshold for
icons, fallback markers and cones. Marker size parameters accept caller sizes;
the default interpolations preserve web sizing. All common colors, opacity and
thresholds live in this package.

The normal exploration-lead icon is precolored artwork, not an SDF image.
`createCheckedExplorationLeadIcon` prepares the green variant from its decoded
image, preserving the white exclamation/outline, antialiasing and alpha.
Register both `EXPLORATION_LEAD_ICON_IDS` images during normal icon preparation
and after style resets. The helper accepts a decoded browser image or raw RGBA
raster and returns a fresh MapLibre raster without another network fetch. Use
the circle fallback if the required icon pair is unavailable. Set opacity on the
layer, not in the raster.

## Shared compass

`@speleodb/map-viewer/heading-compass` exports
`createHeadingCompass(container, { directions, readOnly, onChange })`. It mounts
one local draft control without an outer card. A segmented strip labelled Lead
1, Lead 2 and Lead 3 sits below the existing compass. Switching tabs selects a
saved entry without changing it or replacing the dial, panel, editor or tabs.
Checked tabs use muted green text and a fine bottom accent, with an accessible
status description. Selection retains its separate filled-tab treatment.

The 160-pixel compass retains its shaded face, double rim, ticks, highlighted
north and two-tone red arrow. The full arrow shaft passes beneath the opaque
central editor. Editable and read-only values share the same three-character
width, typography and centered appearance without a degree suffix. They display
whole degrees; existing fractional bearings are rounded for display only and
retain their saved precision until edited.

A compact single-row status panel sits below the lead selector. Its left side
identifies the selected lead and explicitly shows Checked or Unchecked. Its
right side exposes a direct Mark checked or Mark unchecked action. This keeps
the primary action visible without expanding the tabs or adding a progress
footer. There are no checkbox symbols or crossed-out names. Selection alone
never changes status.

When multiple entries exist, Check all and Uncheck all sit above the compass,
aligned to the right and outside the status panel. These compact buttons fit
their labels, keeping the panel at one row. Both remain directly available, with
actions that would change nothing disabled. Enabled buttons use a solid slate
fill, a visible border and bright semibold labels; disabled actions remain
muted. Native buttons use the containing dialog's normal keyboard navigation;
there is no bulk menu. All edits remain drafts until the owner saves. Read-only
mode retains the compass and tab styling, with no bulk actions or bottom status
panel. Checked entries keep their saved compass bearing even though they have no
map cone; each tab still exposes its checked state visually and to assistive
technology.

Plus and minus retain the Save purple and Delete red colors. Plus adds an
unchecked entry with the next unused default bearing. When the selected entry is
undirected, plus says Set direction and sets that entry's heading while
preserving its status. Minus removes the selected entry together with its own
status; remaining entries stay paired with theirs. Removing the final direction
clears its heading but preserves that entry's status. The empty compass state
says No direction set and still exposes its tab and checked state. Clearing the
numeric field also unsets the selected heading. Setting or editing a heading
never resets checked status.

Keyboard arrows and Home/End select tabs. Pointer/touch gestures, keyboard
needle changes and the numeric field edit the selected bearing. Invalid numeric
input must be corrected before switching tabs, adding, checking or saving.
Changes emit fresh arrays and fresh entry objects. Their owner applies them on
Save, discards them on Cancel and retains them after failed saves; the compass
makes no network or storage calls.

`update({ directions, readOnly })` replaces the displayed draft without emitting
a change. `reportValidity()` guards saving against invalid numeric input.
`dispose()` removes owned DOM. No global event listeners, sensor, timer or map
instance is created. Adding, removing, checking or externally updating entries
ends an active pointer gesture so it cannot alter the newly selected entry.

## Verification

Package tests evaluate the real MapLibre expressions for marker filtering,
project gates, status styling and icon/circle opacity. Raster tests preserve
source bytes, white artwork and alpha while checking the green conversion.
Consumer DOM tests exercise the actual compass, draft isolation, checking, bulk
actions, duplicate-bearing removal, null headings, keyboard behavior and
read-only lifecycle. Browser coverage owns native pointer capture, hit testing,
focus and gesture behavior rather than static artwork assertions.
